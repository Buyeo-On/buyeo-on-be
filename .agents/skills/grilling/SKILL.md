# Grilling

공통 이해에 도달할 때까지 사용자의 계획과 결정을 구조적으로 검증한다.

## 설계 트리

- 결정을 선행 조건과 후속 결정이 연결된 설계 트리로 관리한다.
- 선행 결정이 끝나 지금 답할 수 있는 결정 집합을 `frontier`로 본다.
- 한 라운드에 frontier 전체를 질문해 불필요한 왕복을 줄인다.
- 저장소, 문서, 코드, 도구로 확인 가능한 사실은 직접 조사한다.

## 질문 형식

각 질문에 번호와 권장안을 포함한다.

```text
❓ Q1 — 질문 제목: 결정해야 할 내용

➡️ 권장안과 그 이유
```

사용자가 권장안을 그대로 수용하거나 다른 결정을 내릴 수 있도록 선택지의 실제 차이를 설명한다. 중요하지 않은 선호나 구현 중 쉽게 바꿀 수 있는 세부사항은 묻지 않는다.

## 검토 관점

- 사용자 목표와 성공 조건
- 사전 조건과 허용 상태 전이
- 정상·대안·예외 흐름
- 인증과 소유권
- 중복·동시 요청
- 트랜잭션과 실패 복구
- 외부 시스템 실패
- 범위와 명시적 비범위
- 선행 작업과 병렬화 가능성
- 검증 가능한 인수 조건

frontier가 비면 결정 목록과 남은 위험을 요약하고 공통 이해를 확인한다. 확인 전에는 Issue 생성이나 구현을 시작하지 않는다.
