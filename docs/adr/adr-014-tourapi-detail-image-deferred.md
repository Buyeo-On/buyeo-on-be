# ADR-014: detailImage2 도입을 보류하고 대표이미지 결측은 폴백·큐레이션으로 처리한다

- **상태:** 승인됨
- **결정일:** 2026-08-28

## 맥락

ADR-013에서 `detailImage2`를 동기화 범위 밖으로 두었으나, 그 근거는 "이번 범위 아님"이라는 범위 판단이었지 데이터 측정이 아니었다.

현재 `PlaceSyncService`는 `detailCommon2`의 `firstimage`가 비어 있을 때 Kakao 이미지 검색으로 대체한다. Kakao는 웹 검색 결과라 해당 장소와 무관한 사진이 선택될 수 있고 출처가 불명확하다. `detailImage2`(같은 `contentId`의 공식 사진 목록)를 추가하면 이 폴백 의존을 줄일 수 있다고 가정했다.

이 가정을 검증하기 위해 부여 지역(areaCode=34, sigunguCode=6) 전체를 실측했다.

**측정 1 — 대표이미지 결측률** (`areaBasedList2`, 전체 100건 중 `TourApiCategoryMapper` 매핑 대상 77건):

| 카테고리 | 동기화 대상 | 이미지 없음 | 결측률 |
|---|---:|---:|---:|
| HERITAGE | 59 | 3 | 5.1% |
| RESTAURANT | 14 | 7 | 50.0% |
| CAFE | 4 | 0 | 0% |
| 합계 | 77 | 10 | 13.0% |

**측정 2 — `detailImage2` 구제율** (결측 10건 전부에 `imageYN=Y`로 직접 호출):

**10건 모두 갤러리 0장. 구제율 0%.**

`firstimage` 결측은 해당 `contentId`에 이미지 등록 자체가 없다는 뜻이고, `detailImage2`는 같은 등록 데이터의 다른 뷰다. 두 결측은 상관관계가 아니라 원인이 같다.

## 결정

- `detailImage2` 도입을 보류한다. 대표이미지 결측 해소 수단으로는 효과가 0으로 측정되었다.
- Kakao 이미지 검색 폴백을 유지한다. 현재 결측 10건에 대한 유일한 자동 수단이다.
- 결측의 70%(10건 중 7건)를 차지하는 음식점은 수동 큐레이션으로 처리한다. 대상이 14건뿐이라 자동화 비용이 성과를 넘는다.
- `detailImage2`는 프론트에 장소 상세 갤러리 UI 요구가 확정되면 그때 재검토한다. 그 경우의 값어치는 "폴백 개선"이 아니라 "이미 이미지가 있는 67건에 사진을 추가"다.

## 결과

- 장소당 TourAPI 호출이 2회로 유지된다(3회로 늘리지 않는다). 부여 77건 기준 동기화 1회당 약 154회.
- 이미지가 끝내 없는 장소가 남는다. `PlaceQueryService`는 `imageKey`와 `sourceImageHref`가 모두 없으면 `imageUrl`에 `null`을 반환하므로, 클라이언트에 플레이스홀더 처리가 필요하다.
- 측정값은 부여 한 지역·2026-08-28 시점 기준이다. 대상 지역이 늘거나 TourAPI 등록 데이터가 보강되면 재측정해야 한다.
- 음식점 결측 50%는 TourAPI 자체의 데이터 품질 문제이며, 같은 출처의 다른 오퍼레이션으로는 해결되지 않는다.

## 기각한 대안

- `detailImage2` 추가 — 결측 10건에 대한 구제율이 0%로 측정되어 폴백 개선 효과가 없음. 호출량만 1.5배 증가
- Kakao 폴백 제거 — `detailImage2`가 대체하지 못하므로 제거 시 결측 10건이 그대로 이미지 0장이 됨
- 음식점 이미지 자동 수집(크롤링 등) — 대상이 7건이라 수동 처리가 더 싸고, 저작권 판단을 자동화할 수 없음
- 카테고리별 기본 플레이스홀더를 서버에서 채우기 — 실제 사진이 없다는 사실을 데이터에서 감추게 되어, 이후 큐레이션 대상 식별이 어려워짐. 플레이스홀더는 클라이언트 표현 계층의 책임으로 둔다
