# ADR-007: DB 변경과 운영 권한을 분리한다

- **상태:** 승인됨
- **결정일:** 2026-08-09
## 맥락
운영 스키마를 JPA가 임의 변경하지 않아야 하며 애플리케이션 침해 시 DDL 권한까지 노출되는 것을 막아야 한다.
## 결정
- 운영 JPA는 `ddl-auto=validate`를 사용한다.
- 배포 단계에서 Flyway 마이그레이션을 실행하고 성공 후 애플리케이션을 시작한다.
- PostgreSQL Role을 DDL용 `migrator`와 제한된 DML용 `application`으로 분리한다.
- 파괴적 변경은 호환 가능한 단계로 나누고 자동 down migration을 사용하지 않는다.
- RDS 자동 백업은 7일 보존하며 PITR, 삭제 방지와 최종 스냅샷을 활성화한다.
- 애플리케이션은 `Instant`, DB는 `timestamptz`, 시스템 시간대는 UTC를 사용하고 표시·날짜 판정만 `Asia/Seoul`을 사용한다.
## 결과
- 런타임 계정은 스키마를 변경할 수 없고 마이그레이션 실패 시 잘못된 버전이 시작되지 않는다.
- 배포 파이프라인에서 별도 DB 자격증명을 관리해야 한다.
## 기각한 대안
- 운영에서 Hibernate가 스키마를 자동 변경하는 방식
- Spring 런타임 계정 하나에 DDL과 DML 권한을 모두 부여하는 방식
