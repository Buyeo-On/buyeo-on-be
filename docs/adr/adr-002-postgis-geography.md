# ADR-002: 장소 위치는 PostGIS geography로 저장한다

- **상태:** 승인됨
- **결정일:** 2026-08-09
## 맥락
주변 장소·미션 조회와 100m 이내 미션 참여 검증이 필요하다. 위도·경도를 개별 숫자 컬럼으로 저장하면 미터 단위 반경 검색과 공간 인덱스를 직접 지원하기 어렵다.
## 결정
- 장소 위치는 `geography(Point, 4326)` 한 컬럼으로 저장한다.
- `places.location`에 GiST 인덱스를 생성하고 `ST_DWithin`으로 반경을 검색한다.
- API에서는 계속 `latitude`, `longitude`를 주고받고 애플리케이션 경계에서 변환한다.
- 미션 위치는 연결된 `places.location`을 사용한다.
- 미션 참여 반경은 100m 정책값으로 고정하며 DB 컬럼으로 저장하지 않는다.
## 결과
- 미터 단위 거리 계산과 공간 인덱스를 일관되게 사용할 수 있다.
- 배포·테스트 PostgreSQL에 PostGIS 확장이 필요하다.
- `ST_MakePoint` 사용 시 경도, 위도 순서를 지켜야 한다.
## 기각한 대안
- `latitude`, `longitude` 숫자 컬럼만 유지하는 방식
- 숫자 좌표와 `geography`를 함께 저장해 위치를 중복 관리하는 방식
- 고정된 100m 반경을 미션 행마다 저장하는 방식
