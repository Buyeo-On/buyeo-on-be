# ADR-015: TourAPI 대표이미지의 출처와 이용허락 유형을 보존한다

- **상태:** 승인됨
- **결정일:** 2026-08-31

## 맥락

`detailCommon2`는 대표이미지 URL(`firstimage`) 옆에 이미지별 저작권 구분 코드(`cpyrhtDivCd`)를 제공한다. 기존 동기화는 URL만 저장해, 클라이언트가 실제 표시 사진의 제공기관과 공공누리 유형을 정확히 안내할 수 없었다. 같은 데이터셋 안에서도 제1유형과 제3유형 이미지가 섞일 수 있으므로 화면 전체에 단일 유형을 고정하면 사실과 다른 표시가 된다.

## 결정

- 추가 TourAPI 호출 없이 `detailCommon2.cpyrhtDivCd`를 함께 읽는다.
- `Type1`은 `KOGL_TYPE_1`, `Type3`은 `KOGL_TYPE_3`으로 정규화해 `places.source_image_license_type`에 저장한다.
- 누락되거나 알 수 없는 코드는 동기화를 실패시키거나 추정하지 않고 `null`로 저장한다.
- 실제 응답 이미지가 TourAPI `source_image_href`일 때만 `imageAttribution`을 반환한다.
- 관리자 등록 `image_key`가 우선 표시될 때는 TourAPI 이미지 출처를 반환하지 않는다.
- 출처 링크는 공공데이터포털의 한국관광공사 국문 관광정보 서비스 데이터셋 페이지를 사용한다.

## 결과

- 기존 장소는 마이그레이션 직후 이용허락 유형이 `null`이며, 배포 후 관리자 동기화 API를 한 번 실행해야 값이 채워진다.
- 재동기화 전에도 TourAPI URL임을 확인할 수 있으면 제공기관과 서비스는 반환하고, 이용허락 유형만 `null`로 둔다.
- 프론트엔드는 `KOGL_TYPE_1`과 `KOGL_TYPE_3`을 서로 다른 안내 문구로 표시할 수 있다.
- 이미지가 없거나 관리자 이미지가 표시되면 `imageAttribution`은 `null`이다.

## 기각한 대안

- 모든 TourAPI 이미지를 공공누리 제1유형으로 표시 — 실제 제3유형 이미지를 잘못 안내한다.
- 화면 단위 고정 문구만 제공 — 이미지별 이용허락 차이를 표현할 수 없다.
- 알 수 없는 코드를 제1유형으로 간주 — 근거 없는 이용허락 범위를 만든다.
- 별도 `detailImage2` 호출 — 대표이미지 한 장의 유형은 이미 `detailCommon2`에 있어 호출 증가가 불필요하다.
