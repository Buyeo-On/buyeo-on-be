# 약관 동의

## 목적

사용자는 현재 유효한 필수·선택 약관을 확인하고 현재 버전에 대한 동의 상태를 저장한다.

## 사전 조건

- 약관 목록은 로그인하지 않아도 조회할 수 있다.
- 약관 동의 저장은 활성 회원의 유효한 인증 세션이 필요하다.
- 회원은 현재 필수 약관 중 동의하지 않은 항목이 있거나 현재 선택 약관의 동의 상태를 변경하려는 상태다.

## 기본 흐름

1. 앱은 약관 종류별로 현재 시각에 유효한 버전 하나씩을 조회한다.
2. 사용자는 현재 약관의 제목과 본문을 확인한다.
3. 사용자는 서비스 이용약관과 개인정보 처리방침에 동의하고 마케팅 정보 수신 동의 여부를 선택한다.
4. 필수 약관에 모두 동의하면 `동의하고 계속하기`를 누른다.
5. 앱은 현재 약관 전체의 `termId`, `version`, `agreed`를 하나의 `Idempotency-Key`와 함께 전송한다.
6. 서버는 제출한 약관이 현재 버전과 일치하고 필수 약관에 모두 동의했는지 확인한다.
7. 서버는 전체 동의 상태를 하나의 트랜잭션으로 저장하고 같은 확정 시각을 응답한다.
8. 같은 회원이 최초 성공 후 24시간 안에 같은 멱등성 키와 같은 본문으로 재시도하면 최초 성공 응답을 반환한다.
9. 저장이 끝나면 앱은 UC-04의 위치 확인과 디지털 군민증 안내 흐름으로 이동한다.

## 예외 흐름

- 현재 약관을 누락하거나 중복해 제출하면 `400`을 반환하고 기존 동의를 변경하지 않는다.
- 필수 약관을 `agreed: false`로 제출하면 `400`을 반환하고 군민증 안내로 진행하지 않는다.
- 사용자가 약관을 보는 동안 새 버전이 시행되었거나 `termId`와 `version`이 현재 약관과 일치하지 않으면 `409 TERM_VERSION_OUTDATED`를 반환한다. 앱은 약관 목록을 다시 조회한다.
- 같은 멱등성 키를 다른 본문이나 작업에 재사용하면 `409 IDEMPOTENCY_KEY_REUSED`를 반환한다.
- 인증하지 않았거나 세션이 무효하면 `401`을 반환한다.
- 동의 저장 중 하나라도 실패하면 전체 요청을 롤백하고 요청 전 상태를 유지한다.
- 네트워크 응답을 확인하지 못하면 앱은 같은 멱등성 키와 본문으로 재시도한다.

## 범위 경계

- `GET /terms`는 공개 API이며 약관 종류별 현재 버전만 반환한다. 회원의 동의 여부나 과거 버전은 반환하지 않는다.
- 약관에 동의하지 않아 서비스를 이용하지 않는 회원의 탈퇴는 UC-21에서 다룬다.
- 위치 확인과 군민증 생성은 UC-04의 범위다.
- 실제 서비스 약관·개인정보 처리방침·마케팅 정보 수신 동의문 본문과 초기 버전 데이터는 팀이 최종 확정한 후 버전 관리되는 DB 마이그레이션으로 추가한다. 승인되지 않은 임시 본문은 저장소에 넣지 않는다.
