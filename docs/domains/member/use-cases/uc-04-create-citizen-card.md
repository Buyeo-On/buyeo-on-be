# 군민증 생성

## 목적

사용자가 승인된 캐릭터와 카드 테마를 선택하고 위치와 무관하게 디지털 군민증을 한 번 생성한다.

## 사전 조건

- 사용자가 로그인 상태다.
- 사용자가 필수 약관에 동의한 상태다.
- 사용자가 아직 군민증을 발급받지 않았다.

## 기본 흐름

1. 앱은 승인된 프로필 캐릭터와 카드 테마를 조회한다.
2. 사용자는 군민증에 표시될 이름을 지정한다.
3. 사용자는 프로필 캐릭터와 카드 테마를 하나씩 지정한다.
4. 앱은 표시 이름의 앞뒤 공백을 제거하고 하나의 `Idempotency-Key`로 군민증 생성을 요청한다.
5. 서버는 인증, 현재 필수 약관 동의와 미발급 상태를 확인한다.
6. 서버는 표시 이름과 승인된 캐릭터·테마를 확인한다.
7. 서버는 프로필, UUID 형식의 시연용 바코드와 군민증을 같은 트랜잭션과 확정 시각으로 생성한다.
8. 앱은 생성된 군민증을 표시하고 온보딩을 완료한다.

## 예외 흐름

- 필수 항목이 없거나 표시 이름이 정규화 후 1~8자가 아니거나 승인되지 않은 캐릭터·테마를 제출하면 `400 INVALID_REQUEST`를 반환한다.
- 인증하지 않았거나 세션이 무효하면 `401 UNAUTHORIZED`를 반환한다.
- 현재 필수 약관에 모두 동의하지 않았으면 `403 REQUIRED_TERMS_NOT_AGREED`를 반환한다.
- 이미 군민증이 있으면 `409 INVALID_STATE_TRANSITION`을 반환하고 기존 군민증을 유지한다.
- 같은 멱등성 키를 다른 본문이나 작업에 재사용하면 `409 IDEMPOTENCY_KEY_REUSED`를 반환한다.
- 같은 회원이 최초 성공 후 24시간 안에 같은 멱등성 키와 같은 본문으로 재시도하면 최초 성공 응답을 반환한다.
- 생성 중 하나라도 실패하면 프로필, 군민증과 멱등성 기록을 모두 롤백한다.
- 네트워크 응답을 확인하지 못하면 앱은 같은 멱등성 키와 본문으로 재시도한다.

## 범위 경계

- `GET /citizen-cards/options`와 `POST /citizen-cards`만 이 유즈케이스가 소유한다.
- 내 군민증과 바코드 조회는 UC-15가 소유한다.
- 군민증 발급에는 위치 권한이나 부여 지역 진입을 요구하지 않는다. 위치 검증은 여행 시작이 소유한다.
- 실제 캐릭터·테마 이름과 이미지는 디자인 승인 및 S3 업로드 후 버전 관리되는 Flyway 시드로 추가하며 임시 데이터를 넣지 않는다.
- 실제 결제, 포인트 차감과 가맹점 검증은 범위에서 제외한다.
