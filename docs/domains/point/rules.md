# 포인트 도메인 모델과 규칙

## 책임

회원의 포인트 잔액과 내역, 미션 완료 보상과 여행 종료 후 포인트 정산을 소유한다.

## 모델

### 포인트 잔액

회원이 현재 보유한 부여 포인트다.

### 누적 적립

회원이 지금까지 적립한 포인트의 누적 합계다. `EARN` 내역만 더하며 차감·만료·조정 내역은 더하지 않는다.

### 포인트 내역

포인트가 언제, 어떤 활동으로 얼마나 변했는지를 나타내는 기록이다.

### 포인트 정산

여행 종료 후 해당 여행에서 적립하고 아직 정산하지 않은 포인트를 부여에 남기거나 다음 방문까지 유지하는 선택이다.

### 만료 예정

`다음에 이어서 쓰기`로 이월해 아직 만료되지 않은 포인트와 만료 시각이다.

### 포인트 만료

`다음에 이어서 쓰기`로 이월한 포인트가 정산 완료 시각부터 `10×24시간`이 지나 더 이상 사용할 수 없게 된 상태다.

## 정합성 규칙

1. 포인트 잔액이 변하면 반드시 같은 금액의 포인트 내역이 남아야 한다.
2. 포인트 잔액은 유효한 포인트 내역의 합계와 항상 일치해야 한다.
3. 포인트 잔액은 0보다 작아질 수 없다.
4. 하나의 미션 완료에는 포인트 보상을 한 번만 지급한다.
5. 미션 완료, 포인트 내역 생성과 포인트 잔액 변경은 하나의 처리 단위로 본다.
6. 여행 포인트 정산은 해당 여행에서 적립하고 아직 정산하지 않은 포인트만 대상으로 한다. 양수 포인트는 `부여에 남기기`와 `다음에 이어서 쓰기` 중 하나로만 정산하고, 정산 대상이 0이면 사용자의 선택 없이 `NO_POINTS`로 정산한다.
7. 다른 여행에서 이월한 포인트는 현재 여행의 정산 대상에 포함하지 않는다.
8. `부여에 포인트 남기고 가기`를 선택하면 정산 대상 포인트는 더 이상 사용할 수 없고 골목상권 기여로 처리한다.
9. `다음에 이어서 쓰기`를 선택하면 정산 완료 시각부터 `10×24시간` 동안 유지한다.
10. 정산 대상 포인트가 없으면 처리 방법 선택만 건너뛰고 `NO_POINTS` 정산을 기록해 여행을 정산 완료 상태로 전이한다.
11. 정산에 실패하면 잔액과 내역을 정산 전 상태로 유지한다.
12. MVP의 군민증 바코드 조회는 조회 시점의 포인트 내역 `amount` 합계를 반환하고 내역이 없으면 `0`을 반환한다.
13. 군민증 바코드 조회는 포인트 잔액을 차감하거나 포인트 내역을 만들지 않는다.
14. 누적 적립은 `EARN` 유형 포인트 내역의 `amount` 합계로 계산하며 `LEAVE_TO_BUYEO`·`EXPIRE`·`ADJUST`는 포함하지 않는다.
15. 포인트 잔액 요약의 만료 예정 목록은 `다음에 이어서 쓰기` 정산 중 만료 시각이 현재 이후인 항목을 만료 시각 오름차순으로 반환하며, 없으면 빈 목록이다.
16. 포인트 내역 목록은 발생 시각 최신순으로 정렬하고, 같은 발생 시각은 내역 ID로 순서를 정한다. 각 내역의 `balanceAfter`는 발생 시각·내역 ID 순으로 누계한 반영 후 잔액이다.
17. `LEAVE_TO_BUYEO`를 선택해 양수 포인트 정산을 확정하면 badge의 공개 application service를 동기 호출해 `POINT_DONATION_COUNT`를 판정하고 새로 지급된 배지를 정산 response에 포함한다.
18. 앱은 처리 방법을 선택하기 전에 여행별 정산 미리보기로 정산 대상 포인트를 조회한다.
19. `CARRY_OVER` 포인트는 만료 시각이 지나면 멱등한 정기 작업이 해당 금액의 `EXPIRE` 내역을 정확히 한 번 생성해 잔액에서 차감한다.
20. 여행별 정산 대상 포인트는 해당 여행의 `EARN` 내역 합계다. 다른 여행의 이월 포인트와 `ADJUST` 내역은 포함하지 않는다.
21. 전체 잔액이 정산 대상 포인트보다 작으면 다른 여행의 포인트를 대신 차감하지 않고 데이터 불변식 위반으로 정산 전체를 실패시킨다.
22. 포인트 조회와 변경은 응답이나 변경을 처리하기 전에 해당 회원의 만료 도래 이월분을 먼저 `EXPIRE` 내역으로 반영한다. 정기 작업은 포인트 요청이 없는 회원의 만료분을 처리한다.
23. 정산 확정 후 배지 Presigned image URL 생성만 실패하면 정산 semantic result를 유지한다. 같은 멱등성 키 재시도는 저장된 image key로 URL만 다시 생성한다.
24. 포인트 조회와 변경은 활성 회원 행을 먼저 잠근다. 미션 지급, 잔액·내역 조회, 여행 정산과 만료 작업은 이 잠금 순서를 공유한다.
25. 여행 정산은 잠금을 획득한 뒤 DB 시각을 한 번 구해 정산, 여행 상태 전이, 포인트 내역, 신규 배지, 배지 알림과 멱등성 semantic result의 활동 확정 시각으로 함께 사용한다.
26. 만료로 생성한 `EXPIRE` 내역의 발생 시각은 약속된 `expires_at`이고, 정산의 `expired_at`은 만료 처리를 실제로 확정한 시각이다.
27. 정기 만료 작업은 활성 회원별 transaction으로 실행한다. 한 회원의 실패는 다른 회원의 만료 처리를 막지 않으며 실패한 회원은 다음 실행이나 포인트 요청에서 다시 처리한다.

## 상태 전이

| 모델 | 허용 상태 전이 | 규칙 |
| --- | --- | --- |
| 포인트 정산 | 정산 대기 → 부여에 남김, 유지 또는 정산 대상 없음 | 한 번 확정한 정산 결과는 다른 결과로 다시 확정하지 않는다. |
