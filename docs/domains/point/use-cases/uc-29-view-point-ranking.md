# 누적 포인트 랭킹 조회

## 목적

사용자가 다른 참여 회원과 자신의 누적 포인트 순위를 확인한다.

## 사전 조건

- 사용자가 로그인한 활성 회원이다.

## 기본 흐름

1. 사용자가 포인트 랭킹 화면을 연다.
2. 서버가 활성 상태이고 군민증을 발급했으며 누적 적립이 1점 이상인 회원을 대상으로 순위를 계산한다.
3. 앱이 누적 적립 내림차순으로 정렬한 참여 회원 20명과 전체 참여자 수를 표시한다.
4. 앱이 현재 사용자의 랭킹 참여 여부, 누적 적립과 순위를 함께 표시한다.
5. 다음 페이지가 있으면 앱이 응답의 커서로 다음 20명을 조회한다.

## 대안·예외 흐름

- 참여 회원이 없으면 빈 목록, 전체 참여자 수 `0`, 다음 페이지 없음 상태를 반환한다.
- 조회 회원이 군민증을 발급하지 않았거나 누적 적립이 0점이면 내 랭킹을 참여 자격 없음으로 반환한다.
- 해석할 수 없는 커서를 제출하면 목록을 반환하지 않고 `400` 오류를 안내한다.
- 여러 페이지를 조회하는 동안 랭킹 데이터가 변경되면 앱은 새로고침으로 최신 첫 페이지부터 다시 조회할 수 있다.
- 조회에 실패하면 네트워크 오류를 안내한다.

## 규칙

- 누적 적립은 `EARN` 포인트 내역만 합산한다.
- 탈퇴 회원, 군민증을 발급하지 않은 회원과 누적 적립이 0점인 회원은 랭킹에서 제외한다.
- 누적 적립이 같은 회원은 공동 순위를 부여하고 다음 순위는 앞선 회원 수만큼 건너뛴다.
- 동점 참여자는 내부 회원 ID 오름차순으로 정렬하되 회원 ID를 응답에 공개하지 않는다.
- 공동 순위는 페이지 경계에서 나뉠 수 있으며 페이지 크기는 20명으로 고정한다.
- 각 목록 항목은 순위, 현재 표시 이름, 현재 캐릭터 이미지 URL, 누적 적립과 본인 여부를 반환한다.
- 내 랭킹은 모든 페이지에서 전체 참여자 수와 함께 반환한다.
- 조회 회원이 참여 자격이 없으면 `eligible`은 `false`, `rank`·`displayName`·`characterImageUrl`은 `null`, `cumulativeEarned`는 `0`이다.
- 랭킹은 요청마다 최신 확정 데이터를 실시간 집계하며 여러 페이지에 걸친 스냅샷은 보장하지 않는다.
- 랭킹 조회는 회원 행을 잠그거나 이월 포인트 만료를 처리하지 않는다.

## 범위 제외

- 기간별·지역별 랭킹
- 랭킹 검색과 필터
- 과거 순위와 순위 변동
- 랭킹 스냅샷, 캐시와 별도 집계 테이블
- 다른 회원의 ID, 현재 포인트 잔액과 포인트 내역 공개
