# 여행 포인트 정산

## 목적

사용자가 여행에서 남은 포인트의 처리 방법을 선택한다.

## 사전 조건

- 사용자가 활성 회원의 인증 세션으로 로그인한 상태다.
- 여행 세션이 종료된 상태다.

## 기본 흐름

1. 앱이 정산 미리보기를 조회해 이번 여행에서 적립하고 아직 정산하지 않은 포인트와 사용 가능 기간을 표시한다. 다른 여행에서 이월한 포인트는 정산 대상에서 제외한다.
2. 정산 대상 포인트가 없으면 앱이 선택 화면을 생략하고 서버가 `NO_POINTS`로 정산을 완료한다.
3. 정산 대상 포인트가 있으면 사용자가 `부여에 포인트 남기고 가기` 또는 `다음에 이어서 쓰기`를 선택한다.
4. 포인트를 남기면 앱이 골목상권 기여 결과를 표시한다.
5. 이어서 쓰기를 선택하면 앱이 포인트를 정산 완료 시각부터 `10×24시간` 동안 유지한다.
6. 양수 포인트를 부여에 남겨 배지를 새로 획득하면 앱이 정산 response의 배지 ID, 이름, 이미지, 표시 조건과 획득 시각을 보여준다.
7. 앱이 정산 결과를 표시하고 발자취 조회로 이동한다.

## 예외 흐름

- 인증되지 않은 요청은 `401`을 반환한다.
- 존재하지 않거나 다른 회원이 소유한 여행은 두 경우를 구분하지 않고 `404`를 반환한다.
- `Idempotency-Key`가 없거나 형식이 잘못되면 `400`을 반환한다.
- 정산 대상 포인트가 없으면 사용자의 처리 방법 선택만 건너뛰며, `NO_POINTS` 정산과 여행의 정산 완료 상태 전이는 수행한다.
- 정산 대상 포인트가 양수인데 처리 방법이 없거나, 0인데 처리 방법을 보내면 `400` 오류를 안내한다.
- 진행 중이거나 이미 정산된 여행의 미리보기를 조회하면 `409` 오류를 안내한다.
- 전체 잔액이 해당 여행의 정산 대상 포인트보다 작으면 다른 여행의 포인트를 차감하지 않고 정산을 실패시킨다.
- 같은 멱등성 키와 같은 처리 방법의 재요청은 최초 성공 semantic result를 반환하고 배지 Presigned image URL만 새로 생성한다.
- 같은 멱등성 키를 다른 처리 방법이나 operation에 재사용하면 `409` 오류를 안내한다.
- 이미 정산된 여행을 다른 멱등성 키로 다시 정산하면 `409` 오류를 안내한다.
- 정산을 확정한 뒤 배지 Presigned image URL 생성만 실패하면 정산 결과를 유지하고, 같은 멱등성 키 재시도에서 저장한 semantic result로 URL을 다시 생성한다.
- 처리에 실패하면 기존 포인트를 유지하고 오류를 안내한다.

## 인수 조건

- 종료된 본인 여행의 미리보기는 해당 여행의 `EARN` 합계, 만료 도래분을 반영한 현재 잔액과 `240`시간 이월 기간을 반환한다.
- 양수 포인트를 `LEAVE_TO_BUYEO`로 정산하면 해당 금액의 음수 내역을 만들고 다른 여행의 이월분은 유지한다.
- 양수 포인트를 `CARRY_OVER`로 정산하면 잔액을 유지하고 정산 완료 시각부터 `240`시간 뒤를 만료 시각으로 기록한다.
- 정산 대상이 0이면 선택 없이 `NO_POINTS`로 정산하고 포인트 내역을 만들지 않는다.
- 모든 정산 결과는 여행을 `SETTLED`로 전이하며 발자취 조회의 사전 조건을 충족한다.
- `CARRY_OVER` 만료는 논리 만료 시각의 `EXPIRE` 내역과 실제 처리 완료 시각을 정확히 한 번 기록한다.
- 모든 포인트 조회와 변경은 활성 회원 행을 먼저 잠그고 만료 도래분을 반영한 상태에서 응답과 후속 변경을 계산한다.
- 같은 여행의 동시 정산은 하나만 확정하고, 같은 키 replay와 다른 키 재정산을 합의된 멱등성 규칙대로 처리한다.
- 정산, 여행 상태, 포인트 내역, 신규 배지, 배지 알림과 성공 멱등성 결과는 하나의 transaction으로 확정한다.
- 양수 `LEAVE_TO_BUYEO`로 `POINT_DONATION_COUNT` 조건을 처음 충족하면 배지 ID 오름차순 `newlyAwardedBadges`와 배지별 persistent 알림을 반환한다.
- `CARRY_OVER`, `NO_POINTS`와 0포인트 정산은 포인트 기부 배지를 지급하지 않는다.
- 정산 후 Presigned image URL 생성만 실패한 경우 같은 키 재시도에서 확정된 semantic result를 재사용한다.
- 정산 실패는 여행을 `ENDED` 상태로, 포인트와 배지·알림을 요청 전 상태로 유지한다.

## 범위 제외

- `ADJUST` 포인트 내역 생성 기능
- PG 결제, 지역화폐 연동과 실제 가맹점 포인트 차감
- 포인트 만료 persistent 알림과 FCM push
- 발자취 조회 자체 구현
- 승인 badge catalog와 관리자 CRUD
