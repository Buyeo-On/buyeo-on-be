# 알림 도메인 모델과 규칙

## 책임

회원에게 표시하는 알림과 FCM 발송을 소유한다. 알림 동의 설정, 인증 세션과 푸시 토큰의 연결 상태는 회원 도메인이 소유한다.

## 모델

### 알림

포인트 적립, 배지 획득, 주변 퀴즈, 부여 진입, 부여 이탈, 지역화폐 할인, 군민증 발급과 부여 소식을 회원에게 전달한다. `target_type`과 `target_id`는 알림이 가리키는 대상 엔터티에 대한 불투명 참조이며, 실제 값 집합은 각 유형의 알림을 발생시키는 유즈케이스가 정의한다. 알림 조회·읽음 처리 UC는 이 값을 해석하지 않고 그대로 전달한다.

### 알림 발송 자격

회원 도메인의 알림 동의 설정, 기기 권한, 활성 인증 세션과 푸시 토큰을 조합해 현재 회원에게 푸시를 발송할 수 있는지를 나타낸다. MVP는 알림 유형별로 별도 동의 필드를 두지 않고, 근처 퀴즈 알림에서 유래한 단일 동의 필드로 모든 유형의 push 발송 여부를 결정한다. 근처 퀴즈 알림만 이 동의 외에 기기의 위치 권한을 추가로 요구한다.

## 규칙

1. 알림은 발생 시각 내림차순 단일 목록으로 조회하며, 화면은 최근 알림과 지난 알림으로 구분해 표시할 수 있다.
2. push를 발송하는 모든 알림 유형은 회원 도메인의 알림 동의 설정이 동의 상태인 경우에만 발송한다.
3. 근처 퀴즈 알림을 제공하려면 알림 동의 외에 기기의 알림 권한과 위치 권한이 필요하다.
4. 회원이 `다음에 할게요`를 선택하면 기존 알림 설정을 유지한다.
5. 기기 권한이 없으면 알림을 켤 수 없음을 안내한다.
6. 앱은 알림 권한을 얻고 로그인한 뒤 현재 인증 세션의 푸시 토큰을 서버에 등록한다.
7. 서버는 폐기됐거나 만료된 인증 세션의 푸시 토큰으로 알림을 보내지 않는다.
8. FCM이 토큰 만료 또는 무효를 응답하면 서버는 해당 토큰을 삭제한다.
9. 기기 알림·위치 권한은 클라이언트가 관리하며 서버는 권한 상태를 저장하지 않는다.
10. 푸시 토큰 등록 여부와 알림 동의 여부는 독립적이며, 활성 인증 세션의 토큰과 알림 동의가 모두 있어야 push 발송 대상이 된다.
11. 현재 인증 세션의 푸시 토큰을 삭제해도 알림 동의 설정은 변경하지 않는다.
12. 알림 읽음 처리는 멱등하다. 이미 읽은 알림을 다시 읽음 처리해도 읽은 시각과 상태를 그대로 유지한다.
13. 본인 소유가 아니거나 존재하지 않는 알림 ID로 접근하면 두 경우를 구분하지 않고 동일하게 찾을 수 없음으로 처리한다.
14. 배지를 새로 획득하면 배지마다 `BADGE` 알림을 한 건 생성한다. `target_type`은 `BADGE`, `target_id`는 badge ID다.
15. 배지 획득 알림의 제목은 `새로운 배지를 획득했어요!`, 본문은 `{badgeName} 배지를 획득했어요.` 형식을 사용한다.
16. 실시간 획득과 reconciliation 지급은 같은 배지 알림 규칙을 적용한다.
17. MVP의 배지 획득 알림은 persistent 알림만 생성하고 FCM push는 발송하지 않는다.
18. MVP의 이월 포인트 만료는 persistent 알림과 FCM push를 생성하지 않고 `EXPIRE` 포인트 내역과 잔액으로 확인한다.
19. 실시간 배지 알림의 발생 시각은 배지 지급을 유발한 activity가 확정된 시각이며, 배지 도메인이 이 시각을 알림의 공개 application service에 전달한다.
20. 부여 경계 진입을 서버가 재검증했고, 회원에게 진행 중이거나 종료 후 미정산인 여행이 없고, 쿨다운 기간이 지났으면 `BUYEO_ENTRY` 알림을 생성한다. `target_type`과 `target_id`는 없다.
21. `BUYEO_ENTRY` 알림은 배지 알림과 달리 생성과 동시에 FCM push도 발송한다.
22. 부여 경계 이탈을 서버가 재검증했고, 회원에게 진행 중인 여행이 있고, 마지막 `BUYEO_EXIT` 알림 발송 후 쿨다운 기간(12시간)이 지났으면 `BUYEO_EXIT` 알림을 생성하고 FCM push를 발송한다. `target_type`과 `target_id`는 없다.
23. `BUYEO_EXIT` 알림은 진행 중인 여행이 있을 때만 발송하며, 진행 중인 여행이 없거나 이미 종료·정산된 상태면 생성하지 않는다. 기존에 클라이언트가 로컬로 감지해 여행 종료를 제안하는 흐름([UC-23](../trip/use-cases/uc-23-end-trip.md) 규칙5)은 이 알림과 별개로 유지된다.
