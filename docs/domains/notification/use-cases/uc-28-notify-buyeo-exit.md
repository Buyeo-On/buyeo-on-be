# 부여 이탈 알림

## 목적

사용자가 여행 중 부여 경계를 벗어났을 때, 오늘의 여행을 마무리하도록 안내한다.

[UC-23](../../trip/use-cases/uc-23-end-trip.md) 규칙5는 앱이 부여 지역 이탈을 로컬로 감지해 여행 종료를 제안할 수 있다고 정하지만, 이는 앱이 실행 중이어야만 동작하는 클라이언트 전용 흐름이다. 이 알림은 [UC-27](./uc-27-notify-buyeo-entry.md)과 대칭 구조로, 클라이언트가 위치 감지(지오펜스 등)로 부여 이탈을 스스로 감지해 서버에 알리면 서버가 그 주장을 재검증하고 알림 발송 여부를 결정한다. 기존 로컬 종료 제안 흐름을 대체하지 않고 추가한다.

## 사전 조건

- 사용자가 로그인 상태다.
- 앱이 클라이언트 측 위치 감지로 사용자가 부여 경계를 벗어났다고 판단했다.

## 기본 흐름

1. 앱이 사용자의 부여 경계 이탈을 감지하면 현재 위치와 함께 `POST /notifications/buyeo-exit-events`를 호출한다.
2. 서버는 제출된 위치가 실제로 부여 경계 밖인지 재검증한다. 클라이언트의 판단을 그대로 신뢰하지 않는다.
3. 서버는 해당 회원에게 진행 중인 여행이 있는지 확인한다.
4. 서버는 해당 회원에게 마지막으로 부여 이탈 알림을 보낸 시각이 쿨다운 기간(12시간) 이내인지 확인한다.
5. 위 조건을 모두 만족하면(경계 밖, 진행 중인 여행 있음, 쿨다운 경과) `BUYEO_EXIT` 알림을 생성하고 FCM push를 발송한다.
6. 앱은 응답으로 알림 발송 여부를 받는다.

## 예외 흐름

- 제출한 위치가 부여 경계 안이면 알림을 생성하지 않는다.
- 진행 중인 여행이 없으면 알림을 생성하지 않는다. 안내할 여행 종료가 없다.
- 마지막 발송 이후 쿨다운 기간(12시간)이 지나지 않았으면 알림을 생성하지 않는다.
- 인증하지 않았거나 현재 인증 세션이 만료·폐기됐으면 요청을 거부한다.
- 같은 `Idempotency-Key`로 재요청하면 최초 처리 결과를 그대로 반환하며 알림을 다시 생성하지 않는다.

## 범위 경계

- 클라이언트의 부여 경계 이탈 감지(지오펜스 등록·갱신 로직)는 이 UC의 범위가 아니며 클라이언트가 담당한다.
- [UC-23](../../trip/use-cases/uc-23-end-trip.md)의 로컬 종료 제안 흐름과 실제 여행 종료 처리는 이 UC의 범위가 아니다. 이 UC는 push 알림만 추가한다.
- 실제 FCM 발송과 무효 토큰 정리는 [알림 발송 자격](../rules.md) 규칙을 따른다.
- 진행 중인 여행 판정은 여행 도메인의 공개 query seam을 사용하며, 그 판정 기준 자체는 여행 도메인이 소유한다.
