# 부여 진입 알림

## 목적

사용자가 부여 경계 안으로 들어왔을 때, 아직 여행을 시작하지 않은 상태라면 지금 여행을 시작할 수 있다는 사실을 알려준다.

여행 시작(`POST /trips`)의 부여 경계 검증은 이미 여행을 시작하려는 시점에만 발동하는 검증용 체크이며, 이 알림의 의도(여행을 시작하기 전에 먼저 안내)를 충족하지 못한다. 클라이언트가 위치 감지(지오펜스 등)로 부여 진입을 스스로 감지해 서버에 알리면, 서버가 그 주장을 재검증하고 알림 발송 여부를 결정한다.

## 사전 조건

- 사용자가 로그인 상태다.
- 앱이 클라이언트 측 위치 감지로 사용자가 부여 경계 안으로 들어왔다고 판단했다.

## 기본 흐름

1. 앱이 사용자의 부여 경계 진입을 감지하면 현재 위치와 함께 `POST /notifications/buyeo-entry-events`를 호출한다.
2. 서버는 제출된 위치가 실제로 부여 경계 안인지 재검증한다. 클라이언트의 판단을 그대로 신뢰하지 않는다.
3. 서버는 해당 회원이 이미 진행 중이거나 종료 후 미정산인 여행을 가지고 있는지 확인한다.
4. 서버는 해당 회원에게 마지막으로 부여 진입 알림을 보낸 시각이 쿨다운 기간 이내인지 확인한다.
5. 위 조건을 모두 만족하면(경계 안, 진행 중·미정산 여행 없음, 쿨다운 경과) `BUYEO_ENTRY` 알림을 생성하고 FCM push를 발송한다.
6. 앱은 응답으로 알림 발송 여부를 받는다.

## 예외 흐름

- 제출한 위치가 부여 경계 밖이면 알림을 생성하지 않는다.
- 이미 진행 중이거나 종료 후 미정산인 여행이 있으면 알림을 생성하지 않는다. 이 회원은 이미 여행 가능 상태를 알고 있다.
- 마지막 발송 이후 쿨다운 기간이 지나지 않았으면 알림을 생성하지 않는다.
- 인증하지 않았거나 현재 인증 세션이 만료·폐기됐으면 요청을 거부한다.
- 같은 `Idempotency-Key`로 재요청하면 최초 처리 결과를 그대로 반환하며 알림을 다시 생성하지 않는다.

## 열린 질문

- 쿨다운 기간의 정확한 값(예: 24시간, 하루 1회 등)은 아직 정하지 않았다.

## 범위 경계

- 클라이언트의 부여 경계 진입 감지(지오펜스 등록·갱신 로직)는 이 UC의 범위가 아니며 클라이언트가 담당한다.
- 실제 FCM 발송과 무효 토큰 정리는 [알림 발송 자격](../rules.md) 규칙을 따른다.
- 진행 중·미정산 여행 판정은 여행 도메인의 공개 query seam을 사용하며, 그 판정 기준 자체는 여행 도메인이 소유한다.
