# 도메인 지도

이 디렉터리는 코드의 최상위 패키지와 같은 경계로 백엔드 문맥을 나눈다. 에이전트는 전체 문서를 읽지 않고 대상 유즈케이스의 `owner`, `participants`, `policies`, `api`, `adrs`를 따라 필요한 문서만 읽는다.

도메인은 화면이나 저장 방식이 아니라 서비스에서 의미가 있는 상태, 규칙과 변경 책임을 기준으로 나눈다. `배지`를 표준 용어로 사용하며 화면의 `뱃지`와 같은 의미로 본다.

| 도메인 | 소유 상태와 책임 | 코드 패키지 | 문서 |
| --- | --- | --- | --- |
| 회원 | 회원, 소셜 계정, 인증 세션, 약관 동의, 군민증, 프로필, 알림을 포함한 서비스 설정 | `com.buyeoon.member` | [member](./member/) |
| 여행 | 여행 생명주기, 방문 기록, 여행 통계, 발자취 | `com.buyeoon.trip` | [trip](./trip/) |
| 장소 | 장소, 위치, 저장 관계 | `com.buyeoon.place` | [place](./place/) |
| 미션 | 미션, 제출, 도전 기회, 완료, 미션 사진 | `com.buyeoon.mission` | [mission](./mission/) |
| 포인트 | 잔액, 내역, 보상, 여행 정산 | `com.buyeoon.point` | [point](./point/) |
| 배지 | 배지 정의, 조건, 진행도, 획득 | `com.buyeoon.badge` | [badge](./badge/) |
| 알림 | 알림함, 발송 자격 판정, 푸시 발송 | `com.buyeoon.notification` | [notification](./notification/) |

`com.buyeoon.common`은 업무 도메인이 아니라 여러 도메인에 공통인 기술 인프라 경계다. 현재는 멱등성 요청 저장처럼 특정 도메인이 단독 소유하지 않는 영속성 모델만 둔다.

## 핵심 도메인 흐름

1. 사용자가 소셜 계정으로 가입하거나 로그인한다.
2. 신규 사용자가 필수 약관에 동의한다.
3. 필수 약관에 동의한 사용자가 위치와 무관하게 디지털 군민증을 만든다.
4. 디지털 군민증을 발급받은 사용자가 여행을 시작하고 장소와 미션을 탐색한다.
5. 사용자가 미션을 완료해 포인트와 배지를 획득한다.
6. 사용자가 여행을 끝내고 남은 포인트를 정산한다.
7. 사용자가 종료된 여행의 발자취를 조회한다.

## 주요 도메인 사건

| 사건 | 발생 조건 | 후속 영향 |
| --- | --- | --- |
| 회원 가입 완료 | 신규 소셜 계정으로 가입 | 필수 약관 동의가 필요해진다. |
| 필수 약관 동의 완료 | 모든 필수 약관에 동의 | 계정 연동과 군민증 안내로 진행한다. |
| 군민증 발급 | 군민증 정보를 모두 선택 | 가볼 곳을 둘러보고, 부여 안에서 퀴즈 여행을 시작할 수 있다. |
| 여행 시작 | 시작 조건을 충족하고 여행 시작 선택 | 방문·미션·사진·포인트 활동을 여행에 기록한다. |
| 장소 저장 | 장소 상세에서 저장 선택 | 저장한 장소 목록에 반영한다. |
| 미션 완료 | 미션별 완료 조건 충족 | 연결된 문화재 방문 기록을 생성하고 포인트를 적립한 뒤 배지 조건을 확인한다. |
| 배지 획득 | 배지 조건 충족 | 획득 배지와 알림에 반영한다. |
| 여행 종료 | 회원이 여행 끝내기를 확인 | 포인트 정산을 시작한다. |
| 포인트 정산 완료 | 포인트 남기기 또는 유지 선택 | 발자취를 조회할 수 있다. |

## 문서 구성

각 도메인은 다음 문서를 가진다.

- `rules.md`: 도메인이 소유하는 모델, 관계, 불변식과 상태 전이
- `api.md`: 도메인이 소유하는 OpenAPI operation 인덱스
- `use-cases/`: 해당 도메인이 주도하는 개별 유즈케이스

여러 도메인에 공통으로 적용되는 규칙은 [전역 정책](../policies/README.md)에 둔다. API 계약과 데이터베이스 스키마의 원본은 각각 [`raw/openapi.yaml`](../raw/openapi.yaml), [`raw/db-schema.sql`](../raw/db-schema.sql)이다.

## 컨텍스트 로딩 순서

1. 대상 유즈케이스 파일을 읽는다.
2. `owner` 도메인의 `rules.md`와 `api.md`를 읽는다.
3. 유즈케이스가 명시한 `participants`의 관련 문서만 추가로 읽는다.
4. `policies`와 `adrs`에 지정된 문서만 읽는다.
5. 구현 시 필요한 operation과 테이블만 원본 OpenAPI와 DB 스키마에서 확인한다.
