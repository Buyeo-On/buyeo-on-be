# 삭제 정책

1. 로그아웃은 인증 세션만 종료하며 회원, 군민증, 포인트, 여행 기록을 삭제하지 않는다.
2. 저장한 장소 삭제는 회원과 장소의 저장 관계만 삭제하며 장소 정보와 방문 기록은 유지한다.
3. 회원 탈퇴가 확정되면 즉시 로그인을 차단하고 인증 세션을 폐기하며 푸시 토큰과 서비스 DB의 소셜 계정 연결을 삭제한다. 탈퇴 확정 전에 새 소셜 인증 정보로 연결 계정을 확인하고 Apple refresh token을 폐기하거나 Kakao 연결 해제 API를 호출한다.
4. 탈퇴 확정 시각을 파기 대상 시각(`purge_after`)으로 기록한다. 회원 행, 프로필, 군민증, 여행·방문·미션·등록 사진·포인트·저장·배지·알림 설정 정보에 일괄 30일 보관 유예를 두지 않는다.
5. 사진 인증 이미지는 서버에서 관리하며 해당 회원, 여행, 미션 기록과 연결한다.
6. 삭제 작업 일부가 실패해도 탈퇴 회원의 접근 권한을 복구하지 않고 삭제를 다시 시도한다.
7. 탈퇴 회원의 S3 사진 객체를 먼저 삭제하고 객체 삭제가 모두 성공한 경우에만 연결된 관계형 데이터를 삭제한다.
8. 같은 소셜 계정으로 다시 로그인하면 기존 회원을 복구하지 않고 별도의 신규 회원으로 가입한다.
9. 탈퇴 확정 후 첫 정기 작업부터 파기를 시도한다. 기본 실행 간격은 이전 작업 종료 후 1분이며, 데이터 양·장애에 따라 완료 시각은 달라지므로 1분 내 완료를 보장하지 않는다. 이미 삭제된 객체나 행의 재삭제는 성공으로 취급한다.
10. 파기 대상 관계형 데이터 삭제가 완료되면 회원 행까지 삭제한다.

## 출시 전 별도 확인

- V40은 기존 탈퇴 회원의 파기 대상 시각도 탈퇴 시각으로 앞당긴다. 마이그레이션 자체는 사진과 회원 행을 삭제하지 않고 기존 파기 작업이 객체 삭제부터 처리하도록 한다.
- 업로드 URL 발급 시 `mission_photo_upload_reservations`에 객체 키와 생성 시각을 기록한다. 제출 완료 시 예약을 제거하고, 미제출 예약은 생성일부터 24시간이 지나면 객체 삭제 성공 후 제거한다.
- 탈퇴 시 제출 사진과 미제출 예약 객체를 즉시 삭제한다. 탈퇴 뒤 아직 유효한 URL로 지연 업로드되는 경우를 잡기 위해 예약은 회원 연결만 제거한 채 24시간 파기 시점까지 유지한다.
- S3 버전 관리는 비활성화되어 과거 객체 버전은 생성되지 않는다. 완료되지 않은 multipart upload는 버킷 수명 주기 규칙으로 삭제한다.
- 위치 이용·제공사실 확인자료는 `location_usage_records`에 원시 좌표 없이 회원, 기능, 이용 시각과 만료 시각만 자동 기록한다. 기록일부터 6개월 후 정기 작업으로 파기하고, 위치 동의 철회 또는 회원탈퇴 시에는 회원 범위 기록을 즉시 삭제한다.
- 그 밖의 법정 보존자료가 생기면 구체적인 항목·근거·기간을 정한 별도 저장·파기 설계를 추가한다.
- 기존 개발용 약관 시드의 30일 문구는 과거 버전으로 남긴다. 출시 정책 확정 시 새 버전을 등록하고 앱의 안내·동의를 함께 갱신한다.
