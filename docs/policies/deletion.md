# 삭제 정책

1. 로그아웃은 인증 세션만 종료하며 회원, 군민증, 포인트, 여행 기록을 삭제하지 않는다.
2. 저장한 장소 삭제는 회원과 장소의 저장 관계만 삭제하며 장소 정보와 방문 기록은 유지한다.
3. 회원 탈퇴가 확정되면 즉시 로그인을 차단하고 인증 세션을 폐기하며 푸시 토큰과 서비스 DB의 소셜 계정 연결을 삭제한다.
4. 탈퇴 확정 시각을 파기 대상 시각(`purge_after`)으로 기록한다. 회원 행, 프로필, 군민증, 여행·방문·미션·등록 사진·포인트·저장·배지·알림 설정 정보에 일괄 30일 보관 유예를 두지 않는다.
5. 사진 인증 이미지는 서버에서 관리하며 해당 회원, 여행, 미션 기록과 연결한다.
6. 삭제 작업 일부가 실패해도 탈퇴 회원의 접근 권한을 복구하지 않고 삭제를 다시 시도한다.
7. 탈퇴 회원의 S3 사진 객체를 먼저 삭제하고 객체 삭제가 모두 성공한 경우에만 연결된 관계형 데이터를 삭제한다.
8. 같은 소셜 계정으로 다시 로그인하면 기존 회원을 복구하지 않고 별도의 신규 회원으로 가입한다.
9. 탈퇴 확정 후 첫 정기 작업부터 파기를 시도한다. 기본 실행 간격은 이전 작업 종료 후 1분이며, 데이터 양·장애에 따라 완료 시각은 달라지므로 1분 내 완료를 보장하지 않는다. 이미 삭제된 객체나 행의 재삭제는 성공으로 취급한다.
10. 파기 대상 관계형 데이터 삭제가 완료되면 회원 행까지 삭제한다.

## 출시 전 별도 확인

- V39는 기존 탈퇴 회원의 파기 대상 시각도 탈퇴 시각으로 앞당긴다. 마이그레이션 자체는 사진과 회원 행을 삭제하지 않고 기존 파기 작업이 객체 삭제부터 처리하도록 한다.
- 현재 파기 작업의 사진 대상은 `mission_photos`에 등록된 객체다. 미제출 업로드, 이미 발급된 업로드 URL로 탈퇴 후 생성되는 객체, S3 과거 버전·복제·백업까지 지워진다고 간주하지 않는다. 업로드 목록 관리와 저장소 정리 정책을 별도 검증해야 한다.
- 법정 보존자료는 구체적인 항목·근거·기간을 정한 별도 저장·파기 설계가 필요하다. 현재 일반 회원 테이블에 법정 보존 예외나 보존 테이블이 구현됐다고 주장하지 않는다. 특히 위치 이용사실 확인자료는 별도 출시 차단 항목이다.
- 기존 개발용 약관 시드의 30일 문구는 과거 버전으로 남긴다. 출시 정책 확정 시 새 버전을 등록하고 앱의 안내·동의를 함께 갱신한다.
