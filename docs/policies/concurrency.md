# 동시 요청

1. 같은 소셜 계정의 가입 요청이 동시에 들어와도 회원과 기본 서비스 설정은 하나만 만들고 각 성공한 로그인에는 별도 인증 세션을 발급한다.
2. 같은 리프레시 토큰의 갱신 요청이 동시에 들어오면 인증 세션 행을 직렬화하고 가장 먼저 확정된 요청만 토큰을 교체한다.
3. 한 회원의 여행 시작 요청이 동시에 여러 번 들어와도 하나의 진행 중 여행만 만든다.
4. 같은 미션의 완료 요청이 동시에 들어와도 완료 이력, 포인트 보상, 연결된 문화재 방문 기록은 한 번만 확정한다.
5. 같은 배지의 획득 처리가 동시에 실행돼도 배지는 한 번만 지급한다.
6. 동일 회원의 포인트 변경은 한 번에 하나만 확정하며, 다음 변경은 직전에 확정된 잔액을 기준으로 처리한다.
7. 같은 여행의 포인트 정산 요청이 동시에 들어오면 가장 먼저 확정된 결과만 인정한다.
8. 같은 장소의 저장과 삭제가 동시에 요청되면 한 요청을 먼저 확정하고 다음 요청은 확정된 상태를 기준으로 처리한다.
9. 탈퇴와 다른 회원 정보 변경이 동시에 요청되면 탈퇴를 우선하고 이후 변경을 거부한다.
10. 같은 FCM 등록 토큰을 여러 인증 세션에서 동시에 등록하면 마지막으로 확정된 활성 세션 하나에만 연결한다.
11. 서비스 설정 변경은 조회한 버전을 기준으로 한 낙관적 잠금을 사용하며, 같은 버전의 동시 요청 중 먼저 확정된 변경만 성공한다.
12. 같은 인증 세션의 로그아웃과 리프레시 토큰 갱신은 세션 행을 잠가 직렬화하며 최종 상태는 폐기로 확정한다. 갱신이 먼저 성공하면 뒤이은 로그아웃이 새 토큰을 무효화하고, 로그아웃이 먼저 성공하면 갱신을 거부한다.
13. 프로필 수정은 회원 행을 잠근 뒤 현재 프로필을 기준으로 부분 변경한다. 서로 다른 필드의 동시 변경은 모두 보존하고 같은 필드는 가장 나중에 확정된 값을 사용한다.
