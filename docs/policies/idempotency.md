# 중복 요청과 멱등성

1. `Idempotency-Key`가 필요한 요청은 같은 회원이 같은 작업에 같은 키와 같은 요청 본문으로 다시 요청하면 최초 성공 응답을 반환한다.
2. 같은 키를 다른 요청 본문이나 작업에 재사용하면 `409 IDEMPOTENCY_KEY_REUSED`를 반환한다.
3. 이미 완료된 행동을 다른 키로 다시 요청해 허용되지 않은 상태 전이가 발생하면 상태별 오류 코드와 함께 `409`를 반환한다.
4. 다음 행동은 반드시 중복 결과 생성을 막는다.
   - 같은 소셜 계정의 회원 가입
   - 같은 회원의 군민증 생성
   - 같은 장소 저장
   - 같은 미션 완료와 보상 지급
   - 같은 배지 획득
   - 같은 여행의 시작과 종료
   - 같은 여행의 포인트 정산
   - 같은 회원의 탈퇴 상태 전이
5. 장소 저장처럼 HTTP 메서드 자체가 멱등인 작업은 이미 목표 상태이면 성공으로 처리한다.
6. 실패한 요청을 다른 키로 다시 시도한 경우 이전 요청이 실제로 반영됐는지 먼저 확인한 후 처리한다.
7. 소셜 로그인은 `Idempotency-Key`를 요구하지 않는다. 같은 소셜 계정의 동시 가입은 소셜 계정 고유 제약과 트랜잭션으로 회원 중복만 방지하며, 성공한 로그인 요청마다 새 인증 세션을 발급할 수 있다.
8. 성공한 멱등성 요청의 키와 응답은 최초 확정 시각부터 24시간 보관한다. 보관 기간이 끝나면 같은 키를 새 요청에 사용할 수 있고 만료된 레코드는 재사용 처리 또는 정기 정리에서 삭제할 수 있다.
9. 회원 탈퇴는 `Idempotency-Key`를 요구하지 않는다. 성공 즉시 모든 인증 세션이 폐기되므로 회원 행 잠금과 단방향 상태 전이로 중복 처리를 막고, 성공 후 같은 자격 증명으로 재요청하면 인증 단계에서 `401`을 반환한다.
10. 미션 완료와 포인트 정산의 성공 response에는 최초 처리에서 새로 지급된 배지만 `newlyAwardedBadges`로 저장한다. 같은 key의 replay는 현재 획득 상태를 다시 계산하지 않고 최초 처리의 semantic result를 반환한다.
11. `newlyAwardedBadges.imageUrl` 같은 만료되는 Presigned URL은 idempotency response에 저장하지 않는다. 최초 응답과 replay마다 저장한 image key로 새 URL을 생성하므로 URL 문자열과 만료 시각은 달라질 수 있다.
