# Test-driven development

티켓의 인수 조건을 공개 인터페이스에서 검증하는 실패 테스트를 먼저 작성하고, 그 테스트를 통과하는 최소 코드를 구현한다.

## 테스트 seam

- 티켓과 Epic에 합의된 seam을 사용한다.
- 기본값은 HTTP 요청부터 Spring application, 영속성까지 관찰하는 통합 seam이다.
- 복잡한 도메인 규칙은 안정적인 도메인 공개 API에서 빠른 단위 테스트를 추가할 수 있다.
- private 메서드, 내부 호출 순서, 구현 클래스 존재 여부를 테스트하지 않는다.
- Mock은 제어할 수 없는 외부 시스템 경계에 한정하고 내부 도메인 협력을 Mock으로 대체하지 않는다.

## 반복

1. **Red:** 인수 조건 하나를 표현하는 테스트를 작성하고 의도한 이유로 실패하는지 확인한다.
2. **Green:** 테스트를 통과하는 최소 구현을 작성한다.
3. 관련 단일 테스트를 다시 실행한다.
4. 다음 인수 조건으로 이동한다.
5. 모든 동작이 통과한 뒤 중복과 이름을 정리한다.

한 번에 하나의 수직 슬라이스만 진행한다. 실패 테스트 없이 제품 코드를 먼저 쓰거나, 테스트를 통과시키기 위해 인수 조건을 약화하지 않는다.

## 좋은 테스트

- 사용자 또는 호출자가 관찰하는 동작을 검증한다.
- 도메인 언어로 읽힌다.
- 리팩터링 후에도 의미가 유지된다.
- 정상 흐름뿐 아니라 티켓에 포함된 권한, 상태, 중복, 동시성, 롤백 조건을 검증한다.
- 한글로 DisplayName에 테스트가 검증하고자 하는 조건을 명시한다.
- 한글로 테스트 메서드에 주석을 달아 이 테스트에 대해 설명한다.

작업 중에는 관련 테스트를 자주 실행하고, 종료 전에 `./gradlew test`를 한 번 실행한다.
